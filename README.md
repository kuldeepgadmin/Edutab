# Edutab — Campus & Enterprise Management Solutions

A five-page static website for **Edutab**, a technology consultancy delivering ERP setup, website
management, campus portals and fee-gateway integration for schools and colleges.

Built as a dependency-free static site (plain HTML + CSS + vanilla JS) so it can be pushed straight
to GitHub Pages, Netlify, Cloudflare Pages, S3, or any shared hosting space.

## Pages

| File | Section | Purpose |
|---|---|---|
| `sitemap.xml` | — | generated by `tools/set-origin.py` |

| `about.html` | About Us | 15-year background, ERP focus, operating principles, team philosophy |
| `services.html` | Services & ERP Solutions | Four service modules, engagement models, FAQ |
| `workflow.html` | Workflow & Engagement | 4-step deployment model, working principles, terms of service |

Shared assets live in `assets/css/styles.css` and `assets/js/app.js`. No frameworks, no build step,
no external CDN requests — fonts are system fonts, icons are inline SVG, so the site works offline
and loads with zero third-party calls.

## Deploying: GitHub Pages

This repository is ready to deploy directly from GitHub Pages. A workflow publishes the repository
root on every push to `main`.

1. Open the repository on GitHub and go to **Settings → Pages**.
2. Under **Build and deployment**, set **Source** to **GitHub Actions**.
3. Push to `main`, or run **Actions → Deploy static site to GitHub Pages → Run workflow**.
4. GitHub will show the live URL under **Settings → Pages**. For this repository it will be
  `https://kuldeepgadmin.github.io/Edutab/`.

GitHub Pages serves the HTML, CSS, JavaScript, and images in this repository. The Cloudflare Pages
function in `functions/` cannot run on GitHub Pages, so the contact form uses its WhatsApp deep-link
fallback there. The `.nojekyll` file keeps GitHub from applying Jekyll processing.

## Deploying: Cloudflare Pages + Workers

Chosen for global edge performance, a generous free request budget
(**100,000 requests/day** on Workers/Pages Functions) and Cloudflare's DNS,
DDoS and bot-protection layer in front of the site. No build step, no container,
free TLS.

### A. Fastest path — direct upload

```bash
npm i -g wrangler            # or use npx wrangler ...
wrangler login
wrangler pages deploy . --project-name edutab
```

That publishes the folder as-is and registers `functions/api/inquiry.js` as the
form endpoint. Output: `https://edutab.pages.dev` (plus a preview URL per deploy).

### B. Continuous deploys from GitHub

1. Push this folder to a GitHub repo (the git steps are in the appendix below).
2. Cloudflare dashboard → **Workers & Pages → Create → Pages → Connect to Git** → pick the repo.
3. Build settings: **Build command = (blank)**, **Build output directory = `/`**.
4. Save → deploy. Every push to `main` redeploys; every PR gets a preview URL.
5. **Custom domain**: Pages project → *Custom domains* → add `edutab.in`. Cloudflare
   issues and renews the certificate and puts the zone's DNS, DDoS shielding and WAF
   in front automatically. Then run `python3 tools/set-origin.py https://edutab.in`.

### C. Try the form endpoint locally

```bash
cp .dev.vars.example .dev.vars    # optional: fill in delivery secrets
npx wrangler pages dev .          # http://localhost:8788
curl -s -X POST localhost:8788/api/inquiry -H 'content-type: application/json' \
  -d '{"name":"Test","org":"School","email":"a@b.co","interests":["ERP Exploration & Setup"]}'
```

## Contact form delivery

The form posts to `POST /api/inquiry` (a Cloudflare Pages Function). It validates the
input, rate-limits each visitor (6 per 10 min), honours a honeypot field, optionally
verifies a Turnstile token, formats the message and delivers it to **+91 93993 65399**.

Three modes, selected by which secrets exist — so the site works before you configure anything:

| Mode | Requires | What the visitor sees |
|---|---|---|
| **WhatsApp Cloud API** | `WA_CLOUD_API_TOKEN` + `WA_PHONE_NUMBER_ID` | "Inquiry sent ✓" — they never leave the page |
| **CallMeBot** | `CALLMEBOT_API_KEY` | same, one-time free setup below |
| **Deep link** (default) | nothing | WhatsApp opens with the message pre-filled; they press send |

If the function is unreachable, the site is served from a plain static host, or the
network fails, `assets/js/app.js` falls back to building the `wa.me` link in the browser —
**the form still works on GitHub Pages, S3, or a USB stick.** No enquiry is lost; a failed
API delivery also returns the deep link so the visitor can complete it manually.

**CallMeBot one-time setup (free):** send the message `i am using callmebot whatsapp api`
to **+91 733 804 8331** from the WhatsApp number that should receive the key, then copy
the returned `apikey` into the `CALLMEBOT_API_KEY` secret.

**WhatsApp Cloud API (official):** create a Meta Business app → WhatsApp product → copy the
permanent token and the test/production phone-number ID. Senders must reply within the
24-hour customer-service window or use a pre-approved template; for inbound *notifications to
your own number* a plain text message works. Free tier: 1,000 service conversations/month.

To change the destination number, edit **one constant in each place**:
`DESTINATION` in `functions/api/inquiry.js` and `WHATSAPP_NUMBER` / `WA_DISPLAY`
in `assets/js/app.js`.

```bash
git init && git add . && git commit -m "Edutab website"
git branch -M main
git remote add origin https://github.com/<your-username>/edutab.git
git push -u origin main
```

The workflow above is preferred. If you use the legacy branch source instead, choose **Settings →
Pages → Source: Deploy from a branch → `main` / root**. The site appears at
`https://<user>.github.io/edutab/`; `functions/` is inert there, and the form uses its deep-link
fallback.

## SEO: one command when you pick a domain

The site ships **undecided-domain-safe**: every page already has title/description,
Open Graph (`og:site_name`, `og:locale`, `og:title`, `og:type`), Twitter card tags,
`theme-color`, `apple-touch-icon`, JSON-LD structured data (Organization, WebSite,
Service, FAQPage, HowTo, ContactPage) and `noindex` on the 404. What it deliberately
does *not* contain is an absolute `https://…` canonical, because a wrong canonical is
far worse than no canonical.

Two things cover that gap:

1. **Right now, no domain needed.** `assets/js/seo.js` derives `canonical`, `og:url`
   and `og:image` from the live URL at runtime, so the site self-canonicalises correctly
   wherever you put it.
2. **When you settle on a domain, bake it in** so crawlers see the tags without running JS:

```bash
python3 tools/set-origin.py https://edutab.in
# or a GitHub Pages project site (subpath supported):
python3 tools/set-origin.py https://your-name.github.io/edutab
```

That single command writes, idempotently:

* `<link rel="canonical">` + `og:url` + absolute `og:image` (+ size/alt) + Twitter `url`/`image` into all 6 pages
* the `SITE_ORIGIN` constant in `assets/js/seo.js` (switches it from guessing to the fixed value)
* `sitemap.xml` — 5 URLs, real `<lastmod>`, 404 excluded, priority + changefreq
* the `Sitemap:` line in `robots.txt`
* absolute `url`/`@id` inside every JSON-LD block

Verify at any time, and again after any deploy:

```bash
python3 tools/set-origin.py --check
```

It fails loudly if a canonical disagrees with the baked origin, if an old host survives a
domain switch, if `sitemap.xml` is stale, or if the `__EDUTAB_ORIGIN__` token is still
sitting in a file. Changing domains later is safe: previous absolute URLs inside JSON-LD
are normalised back and re-baked.

**Share images** are generated deterministically (no binaries to lose, no AI drift):

```bash
python3 tools/build-social-images.py
```

Produces `assets/img/og-cover.png` (1200×630), `og-cover-square.png` (640×640),
`apple-touch-icon.png` (180) and `icon-512.png` (512) from the brand palette. The script
asserts every text run fits inside the margins and that no two runs overlap, so it fails
instead of quietly exporting a broken card.

After picking a domain, register the site in Google Search Console and submit
`https://your-domain/sitemap.xml`.

## Content protection (what it does and does not do)

`assets/js/app.js` + `assets/css/styles.css` implement:

- text selection disabled across the page (form fields remain fully usable)
- right-click / context menu blocked
- copy, cut and drag-of-content blocked
- `Ctrl/Cmd + C, X, V, S, P, U, A` and `Ctrl+Shift+I/J/C`, `F12` suppressed
- `PrintScreen` blanks the screen with a privacy shield and clears the clipboard while held
- the visible page dims/blanks when the tab loses focus (screen-record tools, capture overlays)
- printing and "Save as PDF" produce only a lock notice page, never the content
- a small toast tells the visitor when a protected action was blocked

**Honest limitation:** no browser can make a public web page literally impossible to reproduce. A
determined user can still photograph a screen or retype content. These measures remove every easy
route and reliably stop casual reuse; they are deterrence, not a cryptographic guarantee. For
genuinely confidential material, put it behind authenticated access.

## Customizing

- **Brand color:** `--violet: #714b97` in `assets/css/styles.css` (`:root`) — every button, chip and
  accent follows it.
- **Content:** each page is hand-written semantic HTML; edit copy directly in the page files.
- **Images:** none required — replaceable CSS/SVG graphics are used so there is nothing to license.
- **Analytics:** none included (keeps the site free of third-party requests).
